SteadyCut

UI Overhaul — React/Vite single-page dashboard, plugin-portable

Re-architect the frontend as a refined single-page dashboard, with all backend access isolated behind one swappable bridge so a future Premiere/DaVinci plugin port only reimplements the bridge — not the UI.

Scope: Full UX overhaul Stack: React + Vite + build step Layout: Single-page dashboard Look: Refined dark + red

Context

The SteadyCut frontend is today a single 1861-line static/index.html — ~630 lines of inline CSS, the rest one big inline <script> driving a 3-step wizard (Footage → Settings → Output). It works but is hard to evolve, and the goal is a full UX overhaul plus a forward-looking constraint: the UI should later port to a Premiere (CEP/UXP) or DaVinci Resolve (Workflow Integration) plugin.

All three hosts — pywebview now, Premiere CEP/UXP, Resolve WI — are the same shape: a Chromium-class webview running HTML/JS, with a host-specific bridge for native actions. The only thing that changes per host is how the UI talks to the backend. Today that transport is split two ways:

  1. window.pywebview.api.* — native dialogs: pick_folder, pick_save_file, reveal_in_finder, open_log (run.py:382).
  2. fetch("/api/...") — FastAPI HTTP: /api/process, /api/status, /api/stop, /api/clip-count, /api/detect-gpu, /api/ffmpeg-status, /api/log-path (run.py:250+).

The porting goal drives the core architectural move: isolate all backend access behind one swappable bridge interface.

Goals & non-goals

  • Goal: React/Vite single-page dashboard, visually a refinement of today's dark+red theme, with a clean host-bridge abstraction.
  • Goal: Keep the backend contract byte-for-byte identical — the ProcessRequest payload (run.py:219), all /api/* routes, and the pywebview js_api unchanged.
  • Non-goal: No backend/pipeline logic changes. No new features. No actual plugin port now — only make it cheap later.

Design system to commit

  • Color strategy: Restrained — neutral dark surfaces + single red accent ≤10% surface + semantic green/amber/red states. Declared, not accidental. Keep the existing brand reds (--accent #ff3b3b for on-dark ink/borders, --accent-solid #e00000 for fills with white text); identity-preservation wins over re-theming.
  • Type: heading/display = a face with identity that is NOT on the tell list (Inter / Roboto / Geist / Space Grotesk / Plus Jakarta / Fraunces all banned by detector). Candidates: Archivo, Hanken Grotesk, Sora. Numerics / timecode / clip counts = a tabular mono (JetBrains Mono or IBM Plex Mono). Dense body may stay a neutral system stack to avoid a second webfont tell. Final face picked in the mockup.
  • Icons: Lucide outline, stroke 1.75, sizes as tokens (icon-sm 14, icon-md 18, icon-lg 24). The header/folder/file SVGs already in index.html are this language; extend it, drop every emoji.
  • Motion tokens: micro 150–300ms, complex ≤400ms; ease-out-quart enter, exit ~70% duration; transform/opacity only; staggered list reveals 30–50ms; all gated by reduced-motion.
  • Z-index scale: dropdown 10, sticky run-bar 20, scrim 30, modal 40, toast 50, tooltip 60. No 999/1000.
  • Spacing rhythm: 4/8px scale; vary section spacing (16/24/32/48) for hierarchy, not uniform.
  • A11y baseline: visible :focus-visible rings on every custom <button> (presets, toggles); 44px min touch/click targets; state never by colour alone (icon+text on success/error).

Deliverable of this phase: DESIGN.md at repo root capturing the above as the build's source of truth. The React components (Phase 1+) and the mockup (Phase 0) both target it.

Architecture (post-approval)

1 · Source layout & build

  • New source dir ui/ (React + TypeScript — typed bridge contract).
  • Vite builds into existing static/ (outDir:"../static", emptyOutDir:true, base:"./" for relative asset paths in the webview).
  • No bundling changes steadycut.spec:39 already ships ("static","static"); run.py:173 mounts it via StaticFiles; / redirects to /static/index.html. Vite just emits static/index.html + assets.
  • Add a build step before PyInstaller in build.sh, build.bat, .github/workflows/build.yml (Node → npm ci → npm run build → pyinstaller).
  • .gitignore: add ui/node_modules/.

2 · Host-bridge abstraction (the portability core)

ui/src/bridge/ — one interface, capability-detected implementation:

  // native actions
  pickFolder(): Promise<string|null>

4 · Single-page dashboard layout (refined dark + red)

Replace the wizard with one scrollable page + a sticky bottom run bar. Port the :root design tokens (index.html:27) into a theme. Sections:

  • Footage — folder input + Browse + live clip-count badge (fetchClipCount, :1282).
  • Settings — preset grid, Analysis Mode toggle, Cut Points toggle, collapsible advanced groups (Stability / Action / Shot Classification / Proxy & Performance) — same controls & conditional visibility (_updateSectionVisibility, :1316).
  • Output — XML path + Save as; reactive live summary (buildSummary, :1521).

Verification

  1. Dev: cd ui && npm install && npm run dev; separately python run.py (Vite proxy → FastAPI). Confirm BrowserBridge HTTP path works, native buttons hidden.
  2. Build: npm run build → confirm static/index.html + static/assets/* emitted with relative paths.
  3. Packaged-path smoke: python run.py serves built static/ via FastAPI + pywebview. Confirm folder pick → clip badge; preset/mode/coa wiring + advanced-group visibility; Detect GPU; FFmpeg banner clears.
  4. End-to-end pipeline: point at a footage folder, Run; verify phase steps advance, clip X/Y, Stop works, success shows XML path + Reveal, timing card + completion ping. Diff the emitted ProcessRequest against the old UI's payload to prove byte-parity.
  5. Frozen build: run existing build.sh end-to-end; launch dist/SteadyCut.app; repeat step 4 inside the bundle.
